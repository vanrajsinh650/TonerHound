2. PHASE A — TABLE STRUCTURE: EXTEND STAGE 7 TO 47 DOCUMENTS
=====================================================================

A.1 — Generalize line-wrap merging

EXP-045's line-wrap merging worked on real_ishares but not on the other 47 documents. Diagnose why:

  For each of the 47 documents with SUB_AMBIGUOUS_OCCURRENCE:
    - Count tables detected by find_tables()
    - Count tables detected by find_tables(strategy="text") for borderless
    - Count physical rows detected
    - Count expected rows from schema array length
    - Compute drift = physical - expected

  If drift > 0: rows are over-segmented (wrapped cells counted as separate rows)
  If drift < 0: rows are under-segmented (merged cells collapsed)

A.2 — Borderless table detection (whitespace method)

For borderless tables where find_tables() fails:
  - Detect column boundaries using vertical whitespace gaps
  - Detect row boundaries using horizontal whitespace gaps
  - Use text line y-positions to infer row structure
  - Reference: PyMuPDF add_lines parameter, "text" strategy

  Build: matching/borderless_table_detector.py

A.3 — Wrapped cell merging (universal)

For every table row where the row height > 2x median row height:
  - Check if the row contains non-numeric text at the top
  - Check if the row contains numeric anchor at the bottom
  - If yes: merge into one logical row
  - Reference: overlap-based row merging (70% overlap threshold)

  Build: matching/wrapped_cell_merger.py

A.4 — Sub-header filtering (universal)

For every row, check:
  - Does it lack a numeric/currency cell? (no $, no comma-number, no decimal)
  - Does it contain a percentage followed by a short title?
  - Is it all-caps or title case with no punctuation?
  - If 2 of 3 match: exclude from row counter

  Build: matching/subheader_filter.py

A.5 — Multi-column reading order (XY-Cut)

For every page with two or more vertical table columns:
  - Apply recursive XY-Cut to detect column boundaries
  - Read column 1 top-to-bottom, then column 2 top-to-bottom
  - Reconstruct row sequence in correct reading order
  - Reference: XY-Cut algorithm, whitespace-gap detection

  Build: matching/xycut_reader.py

A.6 — Page-break row continuation

When a table spans pages:
  - Detect continued header (same header text as page 1)
  - Skip continued header from row count
  - Detect wrapped row split across page boundary (last row of page N, first row of page N+1)
  - Merge if the two halves share a common prefix

  Build: matching/pagebreak_row_joiner.py

3. PHASE B — REAL_INDEXING_MISS (48,120 fields)
=====================================================================

B.1 — Multi-word sequence matching v2

Current multi-token matcher handles up to 3 tokens. Extend to arbitrary length:
  - Build token adjacency graph from VisualLine clustering
  - Use Needleman-Wunsch on token sequences with gaps
  - Allow skip-tokens (e.g. "Bank [of] America" matching "Bank America")
  - Reference: NW sequence alignment

  Build: matching/multitoken_v2.py

B.2 — Character-level n-gram index v2

Current 3-gram index misses some OCR noise. Extend:
  - Build 2-gram AND 3-gram AND 4-gram indexes
  - Query all three, union the candidates
  - Rank by combined n-gram overlap
  - Reject if best candidate scores < 0.4 on char-level Jaccard

  Build: matching/ngram_index_v2.py

B.3 — Consonant skeleton matching

For very noisy OCR:
  - Reduce both tokens to consonant skeletons
  - Match skeletons
  - Recover original if skeleton match >= 0.85

  Example: "Consolidated" → "cnsldtd", "Comsolidated" → "cmsldtd"
  Skeleton similarity: 5/7 consonants match → 0.71

  Build: matching/consonant_skeleton.py

B.4 — Numeric canonical matching v2

For numbers with different formatting:
  - Canonicalize to float
  - Match if float is equal (within 0.01 tolerance for currency)
  - Handle: $1,250.00, 1250, 1250.0, 1,250

  Build: matching/numeric_canonical_v2.py

B.5 — Token proximity reranking

When multiple candidates match the same value, rerank by:
  - Same-page preference
  - Same-row preference
  - Vertical position relative to expected
  - Sibling field alignment

  Uses existing 5D Gaussian reranker + new row-context feature

  Build: matching/proximity_reranker.py

4. PHASE C — TOKEN_SLICING (24,190 fields)
=====================================================================

C.1 — Cell boundary clamping v2

When a token bbox spans multiple cells:
  - Detect cell boundaries from table structure
  - Clamp the token bbox to the containing cell
  - If value spans exactly one cell, use cell bbox
  - If value spans two cells, reject (multi-cell merge)

  Build: matching/cell_clamp_v2.py

C.2 — Column rail detection

Detect column left/right rails from header row:
  - Column 1 starts at header[0].x_left
  - Column 2 starts at header[1].x_left
  - Use rails to constrain candidate x-range

  Build: matching/column_rail_detector.py

C.3 — Character-span sub-slicing

When the gold bbox is for a substring (e.g. "1,250" in "$1,250.00"):
  - Identify the token containing the substring
  - Compute the character position within the token
  - Slice the bbox proportionally

  Reference: linear interpolation of character positions

  Build: matching/char_span_slicer.py

C.4 — Merged cell splitting

When find_tables() returns a cell spanning multiple columns:
  - Detect column count from header row
  - Split the merged cell proportionally by header widths
  - Assign each sub-cell its own bbox

  Build: matching/merged_cell_splitter.py

  Build: matching/region_classifier.py
